# feishuprint 升级设计方案(design.md)

> 日期:2026-07-30 · 方法论:Superpowers 七阶段 · 状态:待健哥签核

## 一、需求本质(Brainstorming 结论)

表面需求是四项功能,真实需求是:**让业务/仓库人员在飞书里点一下就能打出格式正确的出货单**,插件是给非技术人员用的。因此所有设计以"少配置、不��错、格式保真"为第一原则。

## 二、已确认决策

| 决策点 | 结论 | 依据 |
|---|---|---|
| xlsx 渲染路线 | 原生保真渲染(exceljs→HTML) | 用户选定;货单仅10列×14行、21合并单元格,规模可控 |
| 数据对应方式 | 占位符式 `{字段}` + `{#明细}…{/明细}` | 用户选定;实际货单文件已按此写好,零迁移成本 |
| 填充引擎 | 复用 docxtemplater(通用 OOXML) | 实测货单占位符语法与 docx 完全一致 |
| 交付方式 | 逐个交付、逐个验收 | 用户认可 |
| 执行顺序 | #4缩放(已完成)→#2 Excel→#3体验 | 按风险/价值排序 |

## 三、#2 Excel 模板功能设计

### 数据流
```
上传xlsx → 后端校验(.xlsx+PK魔数) → templates/<tableId>/xx.xlsx
打印时: buildPrintData(不变) → xlsxFill(新,docxtemplater填xl/sharedStrings等)
       → 下载xlsx / XlsxPreview(新,exceljs读值+样式→HTML table,复用缩放)
       → 打印: HTML table 直接走 iframe print(天然支持)
```

### 涉及文件
- `server/templateApi.js`:safeName 放开 `.xlsx`;列表过滤同步
- `src/services/xlsxFill.ts`(新):占位符填充+明细循环+自动求和
- `src/components/XlsxPreview.tsx`(新):保真 HTML 渲染+缩放
- `src/components/TemplateManageTab.tsx`:accept 扩展、类型图标
- `src/components/PrintTab.tsx`:按扩展名分流 docx/xlsx
- `scripts/test-xlsx.cjs`(新):**先写测试**(TDD)

### TDD 测试清单(先红后绿)
1. 解析货单模板占位符清单 = 预期字段集
2. 普通占位符填充正确(含中文/特殊字符转义)
3. `{#品名}` 循环 3 条明细 → 生成 3 行,合并单元格/边框随行复制
4. `{合计数量}/{合计金额}` 求和正确(含"12个"/"￥100"式脏数据)
5. 填充后文件可被 exceljs 重新打开(结构未破坏)
6. 明细 0 条时不报错、输出空行

## 四、补充功能建议(基于真实货单的新洞察)

看到货单实物后新增的领域强相关建议(前次通用清单之外):

1. **金额大写**:货单场景刚需。提供 `{金额大写}` 派生变量(数字→"壹万贰仟元整")。
2. **多联打印**:货单角注"白联生产部/绿联销售部/红联客户/蓝联财务/黄联开票"——一键按联数连打5份,可选每联加水印字样。
3. **空明细行补齐**:明细不足固定行数时自动补空行,保证每张单高度一致、裁切对齐。
4. **占位符体检**:上传模板时扫描全部 `{占位符}` 与当前表字段比对,提前红字提示"字段不存在",消灭静默空白。
5. **打印流水**:记录谁何时用哪个模板打了哪条记录(本地jsonl即可),对账可查。
6. 二维码/条码:`{内部货单编号}` 生成条码供仓库扫码(后续可选)。

## 五、风险与边界

- exceljs 打包体积约 1MB(gzip ~250KB),可接受;按需 lazy import 降低首屏影响。
- xlsx 保真度目标:边框/合并/列宽/字体加粗/对齐 100%,复杂填充图案/图表不承诺(货单用不到)。
- 打印用 HTML 路径,与 Excel 原生打印可能有 ±1mm 级差异,验收以实际打印件为准。

## 六、验收标准

- [ ] 上传迪新货单.xlsx 成功并出现在模板库(带类型标识)
- [ ] 选中记录后预览与原 Excel 视觉一致(合并/边框/列宽)
- [ ] 3 条明细正确循环,合计数量/金额正确
- [ ] 下载的 xlsx 用 Excel/WPS 打开无修复提示
- [ ] 预览缩放可用(复用 #4)
- [ ] test-xlsx.cjs 全绿 + tsc 零错误
